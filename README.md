# Code Coach

Code Coach helps you prepare a conversation about a pull request. Run its CLI with `qq`. It returns zero, one or two coaching points, each with code evidence, a reason to discuss it, a question to ask, and a principle to explain.

This is an early local prototype. The TUI and evidence checks work, but the first local-model trial produced reasoning errors, including in the final relevance check. Its coaching judgement is not yet validated. See the evaluation notes before relying on its output.

## Get started

The example needs only Python 3.11 or newer with curses. Live PR analysis also needs Git, an authenticated GitHub CLI, and a running local Ollama model. There are no Python package dependencies. macOS and Linux are supported.

Clone the repository, then run the bundled example. Skip the clone if you already have the checkout.

```sh
git clone https://github.com/suttree/Code-Coach.git "$HOME/src/qq"
~/src/qq/qq --example
```

The example contains two coaching points using real excerpts from Commonbound PR #11. It was curated during development to show the intended output, not generated by the local model. It discusses email latency and keeping a saved action when a courtesy notification fails. The footer and Context view identify it as a curated example. It works offline and is included in the package.

## Use qq as a shell shortcut

For **zsh**, add this line to `~/.zshrc`:

```sh
alias qq="$HOME/src/qq/qq"
```

Then reload it:

```sh
source ~/.zshrc
```

For **bash**, add the same alias to `~/.bashrc` and run `source ~/.bashrc`. If your terminal starts a bash login shell and reads `~/.bash_profile` instead, put the alias there and run `source ~/.bash_profile`.

Adjust the path in the alias if you cloned elsewhere. You can now run:

```sh
qq
qq --example
qq https://github.com/suttree/commonground/pull/11 --repo ~/src/commonground
```

With no arguments, `qq` opens the bundled example. Supplying a PR URL starts live analysis.

Alternatively, make `qq` an executable on your PATH. This also works for scripts and shells without aliases:

```sh
mkdir -p "$HOME/.local/bin"
ln -s "$HOME/src/qq/qq" "$HOME/.local/bin/qq"
```

If `~/.local/bin` is not already on your PATH, add `export PATH="$HOME/.local/bin:$PATH"` to your shell's startup file. For zsh and bash, use the files above and reload them. Other shells have their own PATH configuration. Use either the alias or the symlink; you do not need both. The symlink command stops if that path already exists.

The launcher works from any directory without installing the Python package. It resolves source files relative to its own location, including when launched through a symlink.

## Model and interface

The default model is `qwen3.5:9b-coding`, which was already installed on the development machine. Select another installed model with `--model NAME` or `QQ_MODEL`. QQ never downloads models. The selected model must support Ollama's JSON schema output and `think: false`.

The UI opens immediately and shows progress while GitHub and Ollama respond. A local model can take several minutes. Press `q` to close. Closing the UI does not cancel a request already running in Ollama.

The UI uses pink for titles and the selected tab, orange for the rationale and assumptions headings, and yellow for principles and cited lines. Diff additions are green and removals are pink. It falls back to basic colours or monochrome when needed.

## Navigation

- `Tab` moves to the next section; `Shift+Tab` moves to the previous one. Both wrap around.
- `f` shows the coaching conversation.
- `e` shows cited code with surrounding lines.
- `d` shows the collected diff.
- `c` shows which files and excerpts the model received.
- `n` and `p` move between points.
- `j` and `k`, arrow keys, or Page Up and Page Down scroll.
- `q` quits.

## Evidence and limits

QQ reads GitHub's PR title, description and commit IDs. It compares the head with the merge base and reads tracked source from those commits. It does not check out a branch, edit your repository, run repository code, or post comments.

The local repository's origin must match the PR. Both commits must exist locally. If a commit is missing, fetch it into your checkout before retrying. Automatic fetching and cloning are not implemented yet.

Context selection is deliberately small. It prioritises changed source and selects related files by names and symbols. It reserves space for related code, but does not trace every caller. The Context view discloses truncation and file coverage. Use repeated `--context-file path/to/file` arguments to include a caller, shared component or test you know matters.

Every accepted finding quotes an exact supplied file excerpt at its actual line. If a model gets indentation or a line number wrong, QQ resolves the quote only when it has one unique match in the supplied file. If a citation still fails, QQ asks the model once to correct only the citations, then checks them against the source again. This can fix altered quotation marks without accepting approximate matches. The coaching text stays unchanged and must still pass the relevance check. Unresolved citations, malformed output and model failures are errors. They are never converted into "no feedback". Failed analyses save a `.failure.json` diagnostic beside the evidence packet, including any draft and citation correction received. Citation checks establish that the code exists, not that the model's interpretation is correct. Draft points then pass through a second model call that can discard unsupported or irrelevant claims. It cannot add new points. The Context view shows its decisions. This check uses the same local model and can still make mistakes.

The model can return three outcomes:

- `feedback`, with one or two points.
- `no_feedback`, when the reviewed material does not warrant a coaching conversation.
- `needs_context`, when missing evidence prevents a useful assessment.

No-feedback results are scoped to the supplied material, not a correctness guarantee for the PR.

All inference goes to a localhost Ollama endpoint. No hosted model support is included. GitHub receives the metadata request through `gh`. Obvious credential paths and binary files are excluded, but this is not a general secret scanner. The checkout launcher saves evidence and model output in the project's `.qq/` directory, which is ignored by Git. Treat that directory as source code from the reviewed repository.

## Repeat an assessment

Collect evidence without calling a model:

```sh
qq https://github.com/suttree/commonground/pull/11 \
  --repo ~/src/commonground --collect-only > packet.json
```

Analyse the same evidence again, or reopen a saved result:

```sh
qq --packet packet.json --json > review.json
qq --open review.json
```

`--json` runs without the TUI. `--state-dir PATH` selects where evidence and results are saved. Reopening a result requires neither GitHub access nor a running model.

## Check the prototype

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

The tests cover abstention, missing context, the two-point limit, invalid citations, source selection at historical commits, preserving uncommitted work, sensitive-path exclusions and terminal text handling.

The first real examples are Commonbound PRs #1 and #11. See [the evaluation notes](EVALUATION.md) for results and replay commands. The useful question is whether you would have wanted the proposed conversation at the time. A plausible-sounding answer or a passing citation check is insufficient.
